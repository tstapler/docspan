# Validation Plan: gdocs-sectioned-sync

**Date**: 2026-08-13

## Happy Path Scenario

Given a `markgate.yaml` mapping with `sectioned: true`, `split_level: HEADING_1`, and `local` pointing at an empty directory, when the user runs `docspan pull` against a Google Doc with 5 `HEADING_1` sections plus preamble content and then immediately runs `docspan push` with no edits, then the pull produces `00-preamble.md`..`05-<slug>.md` plus `_manifest.yaml` (6 ordered entries), and the push reassembles them in manifest order producing zero diff against the doc's prior state (fixpoint holds).

## Test Stack

- **Unit**: `pytest` + built-in `assert` (no separate assertion library, matching existing convention), `unittest.mock.MagicMock` for `docs_service`/`drive_service` doubles, `tmp_path` for filesystem isolation — reusing the `make_client`/`make_http_error`/`make_backend` factory fixtures already defined in `tests/conftest.py`. New factories (e.g. a `make_manifest_dir` fixture producing a populated sectioned directory) should follow the same factory-returning-a-callable pattern.
- **Integration**: same `pytest` + `MagicMock`-at-the-`docs_service`/`drive_service`-boundary style already used throughout `tests/test_google_docs_backend.py` and `tests/test_gdocs_push_pipeline.py` — no real network calls, no new test framework or fixture library introduced. "Integration" here means exercising the full `pull_sectioned`/`push_sectioned` call chain (splitter -> manifest -> comment bucketing -> request builder) against a mocked API boundary and real filesystem I/O via `tmp_path`, consistent with how the existing single-file `push()`/`pull()` integration tests are structured.

## Coverage Targets and How to Measure

| Stack | Coverage command | Target |
|---|---|---|
| Python | `pytest --cov=docspan --cov-report=term-missing` | ≥80% line, with 100% line coverage on the new `section_splitter.py` and `manifest.py` modules given they are the highest-novelty/highest-risk code per the plan's Feasibility Risks |

- All public methods on `GoogleDocsBackend.pull_sectioned`/`push_sectioned`, `section_splitter.split_nodes`/`classify_sections`, and `ManifestStore.load`/`save`: happy path + at least one error path covered.
- All external integrations (Docs API `batchUpdate`, Drive comments API, filesystem atomic writes): unit-mocked plus at least one integration test each (see table above).
- The fixpoint test (Story 7.1) and the `sectioned` x `tab_id` matrix (Story 7.5) must pass before Epic 3/7 are considered complete — they are the two acceptance criteria requirements.md calls out explicitly as Success Metrics.
