# Validation Plan: gdocs-sectioned-migrate

**Date**: 2026-08-18

## Happy Path Scenario
Given a Baseline mapping with a committed, clean single-file `local` markdown doc and `sectioned: false`, when the user runs `docspan migrate-sectioned <mapping>`, then the tool produces byte-identical per-section files under a new directory, a fresh `_manifest.yaml`, an updated `markgate.yaml` (`sectioned: true`, `split_level`), an updated `SyncState`, and one git commit whose section files resolve to the original file's pre-split history under `git log --follow -C20%`.

## Test Stack
- **Unit**: pytest (repo convention — flat `tests/*.py`, `python_files = "test_*.py"` per `pyproject.toml`), plain `assert` (no separate assertion library), `unittest.mock`/`pytest` monkeypatch/fixtures for stubbing the Google Docs client and `_run_git`. Note: plan.md's Testing Strategy section names `tests/backends/google_docs/test_migration.py` and `tests/cli/test_migrate_sectioned_cli.py` as if a nested layout exists; the actual repo (`tests/` inspected directly) is flat with no `backends/`/`cli/` subdirectories anywhere (e.g. `test_google_docs_backend.py`, `test_orchestrator.py`, `test_cli.py` all sit at `tests/` top level) — this plan uses `tests/test_migration.py` (new) and extends the existing `tests/test_cli.py` to match actual convention, not the plan doc's aspirational nested paths.
- **Integration**: pytest with `tmp_path` fixture git repos — real `subprocess` calls to a real `git init`'d repo with real commits (not mocked), since the dirty-tree gate and git-history-preservation claims must be proven against real git behavior per plan.md's Testing Strategy. Google Docs API calls are stubbed (no live network).
- **E2E / UX**: manual CLI-driven checklist (no browser surface exists) — each UX acceptance test above is either automated via `CliRunner`/subprocess invocation asserting on stdout+exit code, or a manual audit step where automation would just re-implement the design doc as a test oracle (icon/color reuse, error-state-table completeness).
