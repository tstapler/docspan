# Pre-mortem: gdocs-sectioned-migrate
**Date**: 2026-08-18

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | `_run_git`'s timeout placeholder (`timeout=<small>`, Task 1.1) is calibrated for tiny plumbing calls, but `_commit_swap` (Task 3.2) runs `git add`/`commit` over N newly-created section files from exactly the large docs this feature exists to serve — a big migration commit (possibly with a local pre-commit/lint hook) blows the timeout and aborts mid-write. | `migrate-sectioned` fails with "git command timed out" specifically on the largest, most section-heavy documents — the primary target users hit it, small test docs never do. | Pick and document a generous, explicitly-justified default (e.g. 30–60s, not "small"), make it configurable, and add an integration test that stages a realistically large number of sections (50+) to catch a too-tight timeout before ship. | P1 |
| 2 | No locking beyond `save_config`'s `expected_mtime` check (deferred per pitfalls.md §4): if a second `pull`/`migrate-sectioned`/cron job commits to the same repo while migration is mid-flight, `_rollback`'s `git reset --hard <pre_migration_head>` (Task 4.3) discards whatever the other process committed after `pre_migration_head`, not just migration's own half-done work. | A user or CI bot's unrelated, legitimate commit vanishes from the repo right after a migration failure/rollback elsewhere in the same clone — looks like silent data loss, not a docspan error. | Add a simple per-repo/per-mapping lock (flock-style sentinel file) held for the duration of `migrate_sectioned`'s write phase (steps 5-6), refusing to proceed if held — cheaper than the full pull/push locking work explicitly deferred, and specifically closes the `git reset --hard` blast-radius gap. | P1 |
| 3 | The live Docs API fetch (`client.get_document`, Task 2.1) has no retry/timeout wrapping (adversarial-review.md open concern) — a transient network blip or slow response mid-migration either hangs the CLI or aborts with a raw exception instead of a clear `MigrationError`. | Users report `migrate-sectioned` hanging indefinitely or failing with an unrelated-looking stack trace on flaky networks/VPNs, with no guidance to just retry. | Wrap the fetch with a bounded timeout and a small retry-with-backoff (matching whatever pattern `pull_sectioned`'s own live fetch already uses, if any), surfacing a distinct `MigrationError("could not fetch remote doc: retry")` on final failure. | P2 |
| 4 | `pull --to-sectioned` creates an unsolicited git commit as a side effect of what users mentally model as a read-only sync command (adversarial-review.md open concern); on repos with commit-signing (GPG passphrase prompt) or commit-msg hooks (e.g. requiring a ticket reference), the non-interactive `_run_git("commit", ...)` call hangs waiting for input or fails on a hook the user didn't know would fire. | `pull --to-sectioned` hangs (GPG pinentry) or fails with a hook-rejection message that looks unrelated to "pulling a doc," on any repo with signing/hooks configured — despite the print-parity notice, the notice doesn't warn about hook/signing interaction. | Set `GIT_TERMINAL_PROMPT=0` (and consider `GIT_ASKPASS=echo`) on `_run_git` calls so a signing prompt fails fast instead of hanging, and have the pre-migration notice (Task 5.2/5.3) explicitly mention "this creates a commit using your normal git config, including any hooks/signing." | P2 |
| 5 | Title-normalization for the live/local zip match (Task 2.3) is unspecified — Google Docs auto-converts straight quotes to smart quotes, and titles typed with slightly different whitespace or Unicode normalization (NFC vs NFD, common on macOS-created files) will fail an exact string comparison even though the doc hasn't actually diverged. | Users hit "remote has diverged — run 'docspan pull' first" immediately after a fresh, clean pull, with no actual content difference — the error is unactionable because pulling again doesn't fix it. | Define and unit-test an explicit normalization step before title comparison in `_zip_sections` (Unicode NFC-normalize, strip/collapse whitespace, map curly quotes to straight) so cosmetic Docs-vs-local differences don't trip the drift guard. | P2 |

## P1 Items (address before implementation)
- [x] #1 — RESOLVED via plan.md patch (Phase 4): Task 1.1 now specifies per-call-site timeouts (`_GIT_PLUMBING_TIMEOUT_S = 10` for `rev-parse`/`status`, `_GIT_WRITE_TIMEOUT_S = 60` for `add`/`rm --cached`/`commit`) instead of the `<small>` placeholder. The 50+-section integration test is deferred to validation.md/Phase 5 test authoring (not itself a plan.md structural change).
- [x] #2 — RESOLVED via plan.md patch (Phase 4): new Task 4.5 adds a per-mapping sentinel-lock file (`O_CREAT | O_EXCL`) held for the write phase (Tasks 3.2–4.2), refusing to proceed if already held; the Risks/Mitigations table row (pitfalls.md §4) is updated to reflect this closes the `_rollback`/`git reset --hard` blast-radius gap.
