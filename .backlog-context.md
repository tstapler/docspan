# push preview reports a delete-and-reinsert of identical text as a removal (Priority 3 | Status: in_progress)

## Description
The preview's `N removal(s)` cannot be distinguished from content the author actually
deleted, so a push that will leave the text byte-identical reads as data loss — and
the reverse: real churn reads as ordinary editing.

This is not hypothetical. It is what made me file #40 with a wrong headline: a real
`--dry-run` reported `18 removal(s)` on a design doc, I concluded push would delete 18
lines of code, and it does not — replaying the requests shows the block is
delete-and-reinserted with identical resulting text on every push. The preview was
accurate about the *requests* and actively misleading about the *outcome*.

## What to change

A diff entry whose delete and insert produce the same text is churn, not a removal.
Distinguish them, e.g.:

- report it as `~ rewritten (no text change)` rather than `- removed`, or
- add a summary line naming how many entries are text-neutral churn.

Either way the reader should be able to answer "will this push change what the
document says?" from the preview alone, which today they cannot.

Related: churn is not harmless even when the text is identical — the paragraphs are
destroyed and recreated, so comments anchored to them are lost. That is worth saying
in the message too.
