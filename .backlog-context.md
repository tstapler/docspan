# docspan push does not create a new Google Doc for an unmapped file (Priority 3 | Status: in_progress)

## Description
## What happened

Running `docspan push ` for a local markdown file that has no entry in `markgate.yaml` fails:

```
No mappings found for: ['some-file/README.md']
```

There's no `docspan map` command, and `push`'s `--help` has no create/auto-map flag. Confirmed there's no code path for this in the currently installed `0.2.1.dev2+gf5d742758` build:

- `config.py`'s mapping model declares `remote_id: str` as required — no optional/blank variant.
- `orchestrator.py` and `backends/google_docs/backend.py`'s `push()` always call the Docs API against an existing `doc_id`; there's no `documents().create()` call anywhere.
- `git log --all -S"documents().create"` and `-S"drive().files().create()"` return zero hits across every branch in the repo.

## Why this matters

At least one consumer repo's own docs (`design-docs/README.md`) document the workflow as: write a doc, then "`docspan push` to create" the Google Doc. That's aspirational, not actual — the real flow today requires creating a blank Google Doc out-of-band (Drive UI or API) and manually pasting its ID into `markgate.yaml` before `push` does anything.

## Suggested fix

Support a mapping entry with an empty/omitted `remote_id` (or a new `docspan map  --backend google_docs` command) that creates a new Google Doc via `documents().create()`, writes the resulting ID back into `markgate.yaml`, and then proceeds with the normal push. Confluence backend presumably has the same gap for page creation.
