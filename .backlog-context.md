# google-docs: build() applies an 'equal' restyle against pre-insert coordinates (Priority 3 | Status: in_progress)

## Description
Pre-existing; found while reviewing #41 but reproduces with **pure prose and no code
block**, on `main` and on its parent alike.

## Symptom

A live heading is demoted to `NORMAL_TEXT` and the paragraph inserted above it is
promoted in its place. That destroys the heading's `headingId` — which is what every
internal anchor (#36) resolves against — and any comment anchored to it.

## Reproduction

Document: `HEADING_2 'Overview'` (with `headingId: h.ov`) / `NORMAL_TEXT 'Overview'` /
`'tail'`. Markdown: `## Overview` / `Overview` / `Overview` / `tail`.

```
opcodes: [('insert',0,0,0,1), ('equal',0,3,1,4)]
  insertText           idx 1  "Overview\n"
  updateParagraphStyle [1,10) HEADING_2      <- the newly inserted paragraph
  updateParagraphStyle [1,10) NORMAL_TEXT    <- meant for the ORIGINAL heading
want: [H2, N, N, tail]
got : [N, H2, N, tail]
```

## Cause

When an `insert` group and an `equal`-restyle group share an anchor, the insert is
emitted first (stable sort, `docs_request_builder.py:374-375`), and the restyle's
range is computed from `current[ci].start_index` — a *pre-insert* coordinate.
Inserting 9 UTF-16 units at index 1 moves the original paragraph to `[10,19)`, so
`[1,10)` cannot be it. The arithmetic is unambiguous independent of any simulator.

The same shape steals list bullets (`createParagraphBullets` landing on the wrong
paragraph) when an inserted line matches a list item's text.

## Why it matters more now

Splitting fenced code blocks per line (#40 / #41) does not cause this, but it makes
it far easier to reach: code blocks bring duplicate short lines in bulk (`}`, `);`,
`EOF`, `pass`), and any of them matching a heading or list item elsewhere in the
document triggers it.

## Fix direction

Restyle ranges for `equal` groups must be computed against post-insert coordinates,
or emitted in an order where the insert cannot shift them. Note the requests are
already sorted highest-index-first specifically so they compose — this group is the
