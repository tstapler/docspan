# A multi-paragraph table cell has no faithful markdown rendering (Priority 3 | Status: ready)

## Description
A Google Docs table cell holds a paragraph *list*; markdown's table syntax has no
cell-internal line break. Every encoding tried corrupts something, and #51 settled on
keeping the loud failure:

| encoding | outcome |
|---|---|
| emit the newline | the row ends early, the table reparses as a paragraph — **loud**, visible in the next diff |
| emit `` | table survives, but nothing decodes it back; the table diff key includes cell text, so an *unmodified* push sees a change and deletes/re-creates the table with its comment anchors. Converges after one push, so silent and permanent |
| emit `` and decode on parse | closes that, opens the identical hole for a cell whose author typed `` — `see  tag` becomes `see \n tag`, and a cell holding only `` comes back empty |

Both quiet options were implemented and reverted during #51's review. The loud one is
pinned by `test_a_multi_paragraph_cell_fails_loudly_rather_than_quietly`, and
`unplaced_table_cells` reports such a cell so it is announced rather than merely broken.

A real fix needs something other than markdown's table syntax to carry the break.
Options worth weighing:

- keep the newline but exclude it from the table diff key, so the round trip is lossy
  in the file and idempotent against the document;
- render the cell's paragraphs as an HTML `` when any cell has more than one,
  since docspan already accepts inline HTML elsewhere;
- carry cell structure in sidecar metadata rather than in the markdown body.

Related: #49
